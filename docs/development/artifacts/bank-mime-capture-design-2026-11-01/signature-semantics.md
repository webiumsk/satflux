## Conclusion and severity

**Informational diagnostic limitation, no verified security vulnerability or evidence of forgery.** `invalid_signature` means the verifier completed its pre-crypto profile and found **no eligible bank proof**, with neither a flagged transient resolver failure nor a library `temperror` result. It does not establish that cryptographic signature bytes failed. No proof relaxation or further diagnostic implementation is justified without message evidence.

File evidence: `runtime/bank-mail-verifier/verifier.mjs:155-173`. Every signature must satisfy all proof conditions as one result; passing different conditions across separate signatures is insufficient. A single eligible result succeeds even if another signature fails. The Node reason is preserved through the PHP allowlist, not independently reinterpreted.

`invalid_signature` excludes the earlier explicit unsigned-message, unsupported MIME, invalid identity/sender/content, malformed wire headers and explicit partial-body-signature branches. It also excludes exceptions mapped to retryable verification_unavailable and no-proof cases where the resolver flags temporary failure or any library result is temperror (which become retryable dns_unavailable). It does **not** prove DNS was contacted: syntax/body failure or a blocked key name can prevent a lookup. The 5-lookup local budget also returns ENOTFOUND when exceeded; its no-key result is not a proof of authoritative DNS absence. No actual branch within this category can be identified from the current audit alone.
