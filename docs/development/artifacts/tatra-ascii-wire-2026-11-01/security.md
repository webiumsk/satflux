## Reviewed scope and verified attack boundaries

Owner-supplied safe facts describe a single bank DKIM PASS with signed From/To/Subject, unsigned MIME controls and plain UTF8/7bit/relaxed-relaxed ASCII content. These facts were supplied by main, not independently obtained from a real email. They establish representation compatibility only, not transaction layout, account ownership or settlement.

1. **Unsigned headers cannot select decoded payment text.** `runtime/bank-mail-verifier/verifier.mjs:172-192` admits the new path only for MIME 1.0/plain UTF8/7bit after existing admission checks. It returns the independent canonical ASCII body, never mailparser's decoded text. `ascii-wire-profile.mjs:8-41` performs a bounded linear scan, preserves token/line boundaries, collapses only SP/HTAB, drops trailing whitespace/empty lines and rejects bare CR/LF, high-bit/control data, physical lines over 998 bytes and raw/canonical bodies over 65535 bytes. The existing 262144-byte MIME bound remains. Attack: change unsigned CTE/charset/type/version or duplicate controls to change interpretation. Unsupported variants reject; admitted spelling/WSP variants return identical text. Encoded-looking/nested content remains literal and cannot bypass the strict credit frame. Mitigation and regression tests passed independently.
2. **One same complete bank proof.** Fallback retains bank signer/alignment/key/algorithm/time/full-body/recipient and signed From/To/Subject requirements. `ascii-wire-profile.mjs:45-52` requires case-folded exact relaxed/relaxed, explicitly unlimited body, safe integer lengths and calculated SHA256 equality with both that proof's bodyHash/bodyHashExpecting and exact equality to both canonical lengths. Attack: missing core coverage, another signature supplying missing fields, weak key/algorithm, wrong recipient, future/expired signature, l=, modified body/amount, hash/length mismatch or unsupported modes. These reject with original transient/permanent distinctions. All eligible fallback proofs derive the same fixed relaxed text, preventing signature order/removal from selecting another body mode. Raw contentSha256/recipient binding remains unchanged.
3. **Legacy signed-MIME precedence and result shape preserved.** The complete original proof predicate is text-identical and evaluated first. Fully signed MIME keeps its original decoded body and no bodyProfile. Only successful fallback adds fixed `tatra-ascii-relaxed-v1`. Actual synthetic legacy QP/base64/7bit results were compared with mounted baseline406; body and shape match exactly, including precedence over another fallback proof. Existing CLIs, dependencies and diagnostic sanitizer remain byte-identical. Diagnostic v1 shape is unchanged; MIME-required flags become false only for a selected fallback. Old captured original summaries remain readable and unchanged.
4. **Pure private operator profile facts.** `BankMimeCaptureService.php:174-182` adds only fixed outer profile strings after a validated recheck. Lines 189-215 map known profile enums and run only pure `TatraBankSepaEvidenceParser::parse` for verified, bounded, valid UTF8 text and a recognized representation. Output is matched/unsupported/not_evaluated; references/identity/account/amount/text are discarded. Unknown profile values cannot echo and suppress parsing. The identical-cipher/absolute-expiry guard remains after all analysis. Attack: arbitrary profile marker, invalid type/size/encoding, unverified/unsupported body or expiry during analysis. Tests assert no private output, record/TTL change, financial import/report, audit-as-paid, queue or HTTP side effect. Matched means frame compatibility only.
5. **Financial, tenant and privacy invariants unchanged.** Fifteen preserved-file byte comparisons passed: strict/diagnostic/Company CLIs and extractor, package/lock, job, webhook controller, inbound email/address services, general/strict Tatra parsers, SEPA confirmation service, PHP diagnostic runner and capture config. Existing owner binding, encrypted queue/one-shot capture, account/amount/reference/provider and once-only guards remain. Cross-profile tests verify identical reference/account/amount/currency/dedup key/origin flag across old/new/WSP variants. Auth/CSRF, support exception, merchant secrets/recovery phrases, billing/entitlements and Evolu were not changed; no fresh whole-application audit of them is claimed.
